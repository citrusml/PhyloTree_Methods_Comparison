### 【実装プラン】ICS (Invariant Category Sites) シミュレーション条件の導入

#### 1. Dayhoff カテゴリーと ICS 置換行列の数学的定義
- **Dayhoff 6 分類グループ**:
  - Group 1 (Small / Tiny): `A, G, P, S, T`
  - Group 2 (Acidic / Amide): `D, E, N, Q`
  - Group 3 (Basic): `H, K, R`
  - Group 4 (Aliphatic / Hydrophobic): `I, L, M, V`
  - Group 5 (Aromatic): `F, W, Y`
  - Group 6 (Sulfhydryl): `C`
- **ICS 交換可能性行列 $S^{\mathrm{ICS}}$ の構築**:
  - 標準LGモデルの $20 \times 20$ 対称交換可能性行列 $S^{\mathrm{LG}}$ および平衡アミノ酸頻度 $\pi^{\mathrm{LG}}$ をベースとする。
  - アミノ酸ペア $(u, v)$ について:
    $$S^{\mathrm{ICS}}_{uv} = \begin{cases} S^{\mathrm{LG}}_{uv} & (\text{アミノ酸 } u \text{ と } v \text{ が同一の Dayhoff グループに属する場合}) \\ 0 & (\text{アミノ酸 } u \text{ と } v \text{ が異なる Dayhoff グループに属する場合}) \end{cases}$$
  - 平衡頻度は $\pi^{\mathrm{LG}}$ をそのまま指定し、PAML 形式（下三角 190 要素 + 頻度 20 要素）で NEXUS モデルファイルに出力する。
  - これにより、特定カテゴリーのアミノ酸から開始したサイトはカテゴリー内でのみ置換が起こり、カテゴリー外への遷移確率が厳密に 0 となる。

#### 2. AliSim での実現可能性調査結果（検証済み）
- **モデル定義ファイル (`--mdef`)**:
  - `#nexus begin models; model ICS = ...; end;` 形式のファイルを動的に作成し、AliSim に `--mdef <file.nex>` で渡すことで自作モデルが利用可能。
  - 自作モデル名の場合は `--seqtype AA` を明示することで正しくアミノ酸モデルとして認識される。
- **パーティションシミュレーション (`-q`)**:
  - AliSim では `-q <partition.nex>`（Edge-linked equal partition model）を使用することで、同一配列内に通常領域（`LG+G4{alpha}`）と ICS 領域（`ICS+G4{alpha}`）を混在させたシミュレーションが可能。
- **Indelモデル・枝長スケーリング・ランダム樹生成との併用**:
  - `--indel <ins>,<del>`, `--branch-scale <dist>`, `-t RANDOM{bd{...}}` との組み合わせが正常に動作することを実機検証済み。

#### 3. 具体的な実装設計 (`bin/simulate_data.py` の拡張)
- **引数の追加**:
  - `--ics_prop` (float, default: `0.0`): 配列全体に対する ICS サイトの割合 ($0.0 \le p \le 1.0$)。
- **処理フロー**:
  1. `ics_prop == 0.0` の場合:
     - 従来の単一モデルシミュレーション（`-m LG+G4{alpha} --length L`）をそのまま実行（既存の実験との完全な後方互換性を保持）。
  2. `ics_prop > 0.0` の場合:
     - $S^{\mathrm{ICS}}$ を計算し、一時 NEXUS モデルファイル（`ics_model_<pid>.nex`）を出力。
     - 配列長 $L$ から $k = \mathrm{round}(L \times \mathrm{ics\_prop})$ 個のサイト位置をランダムサンプリング（ランダム配置）。
     - 残りの $L - k$ 個を通常 LG 領域として、NEXUS パーティションファイル（`partition_<pid>.nex`）を出力:
       ```nexus
       #nexus
       begin sets;
           charset part_lg = 1 3 4 6 7 ...;
           charset part_ics = 2 5 8 ...;
           charpartition mypart = LG+G4{1.0}:part_lg, ICS+G4{1.0}:part_ics;
       end;
       ```
     - AliSim コマンドを実行:
       ```bash
       iqtree3 --alisim <prefix> \
               --mdef ics_model.nex \
               -q partition.nex \
               --seqtype AA \
               -t RANDOM{bd{0.1/0.05}/N} \
               --indel 0.05,0.1 \
               --branch-scale <distance> \
               -seed <seed> \
               --redo
       ```
     - 出力された True Tree, True MSA, Unaligned FASTA を抽出し、一時 NEXUS ファイル等をクリーンアップ。

1. ユーザーからのご指摘の検証と真因究明
Q1. 「C は ICS サイトならば不変サイトにするので良いのでは？」<br>
結論: ユーザーのご指摘が完全に正しいです。
Dayhoff 6 分類において C（システイン）はメンバーが 1 つだけのグループ（Group 6: {C}）です。
Dayhoff カテゴリー間の置換を許さない（ICS）定義に厳密に従えば、ICS サイトにおいて C は他のどのアミノ酸にも置換できないため、厳密な「不変（constant / invariant）」サイトとなります。
数学的には $S^{\mathrm{ICS}}_{C, X} = 0 ; (\forall X \neq C)$ であり、遷移確率行列において $P(C \to C, t) = 1.0, P(C \to X, t) = 0.0$ となる完全に正当なマルコフモデルです。
Q2. 「models/ics_model.nex はあっていそう？」<br>
結論: 異グループ間をすべて 0.0 にした厳密な ICS 行列が理論的に 100% 正しいファイルです。
models/ics_model.nex は、Dayhoff 6 分類に沿って同一グループ内のみ LG の交換可能性を保持し、異グループ間（C を含む）は厳密に 0.000000 に設定されています。
Q3. 「というか C が遷移しない状態でもなぜエラーが出た？」<br>
結論: エラーは C の不変性のせいではありません。IQ-TREE AliSim の Indel + パーティションシミュレーションにおける既知のメモリバグ（PR #88: first_insertion ポインタ解放エラー）が原因です。
検証実験の結果:
単一モデル + Indel: 厳密な ICS モデル（C が不変）単独で --indel をつけても BUS ERROR は発生せず正常終了する。
標準モデル（LG + WAG）のパーティション + Indel: 自作 ICS モデルを使わず、IQ-TREE 標準の LG と WAG のパーティションであっても、-q と --indel を併用すると全く同じ BUS ERROR: PhyloTree::initSequences でクラッシュする。
2. 対策と実装変更
IQ-TREE の -q partition.nex と --indel の組み合わせバグを完全回避しつつ、指定割合の ICS サイトと LG サイトを同一アライメントに生成する Tree-linked 2段階シミュレーション を 
bin/simulate_data.py
 に実装しました。

処理フロー:
- 同一の系統樹 $T$ を生成: LG 領域（$L_{\text{LG}} = (1 - \text{ics_prop}) \times L$）を Birth-Death モデルでシミュレーションし、True Tree $T$ を出力。
- ICS 領域のシミュレーション: 同一の True Tree $T$ 上で、ICS 領域（$L_{\text{ICS}} = \text{ics_prop} \times L$、C は不変）を単一モデルとしてシミュレーション。
- 配列の結合: Taxon ごとに配列を結合して出力。

これにより、IQ-TREE のパーティション Indel クラッシュを 100% 回避。


**最終的にはこうなりました。**
具体的な処理内容:
LG 領域のシミュレーション:
系統樹 $T$ 上で、可変領域（$L_{\text{LG}} = (1 - \text{ics_prop}) \times L$）に通常の --indel 0.05, 0.10 を適用してシミュレーション。
ICS 領域のシミュレーション（Indel なし）:
同一の系統樹 $T$ 上で、ICS サイト（$k = \text{ics_prop} \times L$）を Indel なし（置換のみ、C は厳密不変） でシミュレーション。
アライメントへのインターリーブ（分散配置）:
LG 領域の間に、ICS サイト（$k$ 個）を均等に挟み込んで 1 つのアライメントに統合。
検証結果:
全 Taxon において、ICS サイトは一切欠失せず 100% 確実に存在（Gaps in ICS = 0）。
ICS サイトでの Dayhoff カテゴリー間変異は 0 件（完全保証）。
LG 領域には自然な Indel が発生し、アライメント全体に ICS サイトが自然に分散。
IQ-TREE のクラッシュは 100% 根絶。
